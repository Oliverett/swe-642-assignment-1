SWE642 Assignment 1

Documentation for: Containerization (Docker), CI/CD (Jenkins), and Kubernetes Deployment (kubectl + Service resiliency).

1. What I built

I built a single-page portfolio and student survey web application (Homework 1 – Part 2). The application includes:

  • A tabbed interface (Home, About, Skills, Student Survey, Contact) using Bootstrap 5.
  • Cookie-based greeting for the Student Survey.
  • Student Survey form validation in JavaScript.
  • Zipcode lookup using an AJAX request to zipcodes.json.
  • Computed statistics (Average and Maximum) from 10 comma-separated numbers.

The app is containerized with Docker and deployed to Kubernetes using a Deployment (3 replicas for resiliency) and a Service (LoadBalancer).

2. How it works (high-level architecture)

Developer machine
Edits code locally and pushes to GitHub.

Jenkins CI/CD pipeline
Checks out code, builds a multi-arch Docker image, pushes it to Docker Hub, and redeploys to Kubernetes.

Kubernetes cluster
Runs 3 pods from the container image and exposes the app via a Service.

3. Project files

  • index.html - main website and survey UI
  • zipcodes.json - data for zipcode lookup
  • profile.jpg - image used in the About tab
  • Dockerfile - builds an Nginx container that serves the static files
  • k8s-deployment.yaml - Kubernetes Deployment + Service

4. Containerization with Docker

4.1 Dockerfile behavior

The container uses nginx:alpine, removes the default Nginx HTML directory, and copies in: index.html, zipcodes.json, and profile.jpg.

4.2 Local build and test

docker build -t swe642-assignment1 .
docker run --rm -p 8080:80 swe642-assignment1

Then open: http://localhost:8080

5. Docker Hub image tagging

The Jenkins pipeline pushes two tags each run:

  • oliveret/swe642-assignment1:${BUILD_NUMBER}
  • oliveret/swe642-assignment1:latest

Using a unique build tag makes it easier to track which version is running in Kubernetes.

6. Kubernetes deployment with kubectl

6.1 Kubernetes resources

The file k8s-deployment.yaml defines:

  • Deployment: replicas: 3 to ensure resiliency.
  • Container port: 80.
  • Service: type LoadBalancer and forwards port 80 to the pods.

6.2 Apply and verify

kubectl apply -f k8s-deployment.yaml
kubectl rollout status deployment/swe642-assignment1-deployment
kubectl get pods -l app=swe642-assignment1
kubectl get svc swe642-assignment1-service

6.3 Accessing the application

If EXTERNAL-IP remains pending (common for local clusters), use port-forward: 

kubectl port-forward svc/swe642-assignment1-service 8081:80

Then open: http://127.0.0.1:8081

Rancher and EKS management

I imported my existing AWS EKS cluster into Rancher using the Rancher UI. Rancher is used to manage/monitor the EKS cluster, while the Kubernetes Deployment and Service run the containerized application on EKS.

If NodePort is available, the Service’s mapped port may also be usable (for example 80:31169).

7. Resiliency requirement (3 pods)

Baseline configuration uses replicas: 3 in the Deployment. If a pod is deleted, the ReplicaSet creates a replacement automatically.

7.1 Resiliency test commands

kubectl get pods -l app=swe642-assignment1 -o wide
kubectl delete pod <one-pod-name>
kubectl get pods -l app=swe642-assignment1 -w

8. CI/CD pipeline with Jenkins

8.1 Jenkins installation (local)

Jenkins was installed using the downloaded jenkins.war and a supported Java runtime. Jenkins is started with: 

export PATH="/opt/homebrew/opt/openjdk@21/bin:$PATH"
java -jar ~/Downloads/jenkins.war --httpPort=8080

Then open: http://localhost:8080 and complete the setup wizard using the initial admin password.

8.2 Jenkins configuration

  • Credentials: Added Docker Hub credentials in Manage Jenkins → Credentials with ID: dockerhub-creds.
  • Pipeline job: Created a Pipeline job pointing to the GitHub repository and using: Jenkinsfile.

8.3 Jenkinsfile stages

  • Checkout: Pull source from GitHub.
  • Build and Push Multi-Arch Image:
    • Logs into Docker Hub
    • Uses Docker Buildx to build for linux/amd64 and linux/arm64
    • Pushed image tags: build-number tag and :latest
  • Deploy to Kubernetes:
    • kubectl apply -f k8s-deployment.yaml
    • kubectl set image to update the deployment to the new build tag
    • Waits for rollout completion with kubectl rollout status

9. Kubernetes deployment details (kubectl)

Deployment is updated by setting the container image in the Deployment spec and letting Kubernetes handle the rolling update (while ensuring that desired replicas remain available).
